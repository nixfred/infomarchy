# Changelog

All notable changes to Infomarchy. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [SemVer](https://semver.org/).

## [Unreleased]

### Added
- **The desk can live on one workspace instead of all of them.** (#38, @shieldsworks) `omarchy-shell infomarchy setDeskWorkspace 5` draws the cards only while workspace 5 is the one on screen; `0`, the default, keeps today's behaviour of every workspace. A background-layer surface belongs to an *output*, not a workspace, and Hyprland draws it under every workspace on that monitor, so there is no layer-shell property that could express this, so the gate has to sit on the view. It gates the **cards only**: the wallpaper keeps rendering everywhere, because hiding the `PanelWindow` would take the wallpaper with it and leave the other workspaces on the flat theme colour. Each screen answers for itself, from the `activeWorkspace` the panel already resolves for its fullscreen check, so a second monitor showing that workspace shows the desk too. While the workspace is still unknown (early in startup, before the Hyprland monitor resolves) the desk stays visible rather than blinking out, since an unset gate must never be why the dashboard is missing. Special workspaces carry negative ids and are refused, as is anything above 999; an out-of-range value is rejected with a usage string rather than clamped, so a typo cannot quietly pin the desk to workspace 1. The SUPER+D overlay is unaffected and still summons over any workspace.
- **FLEET: other machines' AI agents, seen over SSH.** Closes the "Fleet row" roadmap item. `INFOMARCHY_FLEET_HOSTS` names one or more ssh aliases — the same aliases you'd already type after `ssh` yourself, with user, identity file and proxy jump staying in `~/.ssh/config`, never in this variable. Each host gets one bounded, read-only `ps -eo pid=,args=` probe per 30 s refresh, matched against the identical `providerOf()` regex table local detection already uses (passed in by reference from `collector.ts`, not duplicated), so a remote Hermes, Claude, Codex or anything else `PROVIDERS` recognises shows up exactly the way a local process would. An unreachable host reads **unreachable**, never fabricated, and a genuinely idle-but-reachable host reads **idle** — `sqlite3 -json`'s empty-array-vs-empty-string distinction made that call precise instead of guessed. Unconfigured, FLEET costs one environment read per tick and nothing else; the card itself stays invisible until a host is actually configured.
- **Hermes/OpenRouter usage in USAGE & LIMITS**, for whichever FLEET hosts run Hermes — no second API key to hold anywhere on the machine, since everything comes from files Hermes already keeps on the host. Token counts and the per-model breakdown come from Hermes's local billing ledger (`~/.hermes/state.db`, `sqlite3 -readonly -json`); dollar figures and a new **MONTHLY** limit bar come from Hermes's own cached snapshot of OpenRouter's key-usage API (`~/.hermes/workspace/openrouter_key_usage.json`), read in the same SSH round trip. The two are deliberately separate sources: caught live, before merge, that the ledger's own per-row cost sum is *not* lifetime spend — it's only as old as Hermes's current session-tracking window, which undercounted a real account's true lifetime total by roughly 30× against openrouter.ai's own dashboard. The ledger's per-row estimate is now a fallback, used only when the key-usage file is absent; the card's status line says which source produced the figure on screen. `pricing.json`'s pinned LiteLLM snapshot still has no entries for most OpenRouter model ids, which is why this is the one usage row that never goes through it.
- `INFOMARCHY_SKIP_FLEET=1` disables both of the above, the same shape as `INFOMARCHY_SKIP_GITHUB`.
- **FLEET sessions: which remote agent needs you, and one click to get there.** (#37, @RidgetopAi) The `ps` probe above answers "is anything running over there": a count. When a fleet host runs Infomarchy itself, its row now expands into one line per remote session with project, working/idle state, and a **NEEDS YOU** tag, derived on the far end by the same code the local session cards use; the card glows when any remote session is waiting. Clicking one opens a terminal, `ssh`es over and jumps into that tmux window and pane, the local jump displaced by one hop, with every id validated on the way out and again where it becomes a command line. This layers on the `ps` probe rather than replacing it: a host with no `bun` or no Infomarchy reports `unsupported` (a status, not an error), keeps its original row untouched, and is re-asked every 10 minutes instead of every 30 seconds, so a fleet of plain ssh boxes costs nothing extra. The probe runs the session scan only (no telemetry, network, Ollama, GitHub or history walk): 0.65 s on a live 3-session host. Only session-level facts cross the boundary: provider, project basename, attention state and its canned reason, busy/stale/uptime, and the tmux address. The window title that produced the attention state, the attention detail that quotes it, prompt text, paths and git state do not. One function builds that row on the sending side, and the receiving side re-validates, clamps and type-checks all of it rather than trusting a remote to have obeyed. `INFOMARCHY_SKIP_FLEET_SESSIONS=1` disables the layer and leaves the `ps` rows. See [FLEET sessions](docs/fleet-sessions.md).
- **Optional APPS module: local development servers on the desk, managed as systemd user services** (#36, @auggernaut). A dev server started in a terminal outlives the terminal, and the next task cannot find it, so it gets started again on a different port. The module registers a checkout with the command it already has and a fixed port, then lets systemd own the process: the desk asks for actions and reads status, so hiding the desk or closing an agent task never stops an app. Cards show HTTP readiness, the served checkout, branch, changed-file count and the last 100 log lines, with Open, Start/Stop, Restart, Logs and Edit. The bundled `infomarchy-apps` CLI gives any agent or terminal the same `ensure` operation, which reuses a running service or starts it and waits for readiness.

  This is the first thing in the plugin that writes outside its own config, so the boundaries are the point. It refuses to replace any unit file not carrying its own `# Managed by Infomarchy Apps` marker, or any `~/.local/bin` entry that is not its own symlink. A port already in use is reported with the owning PID and directory and is never killed, adopted or silently swapped for another port; ownership is proven through the service cgroup rather than assumed. Commands are argument arrays with quoting only, no shell operators, expansion or redirection. Registration and editing neither start the app nor touch its package scripts, and login startup stays off until asked for. Lifecycle calls are serialized per app with `flock`, a failed edit restores the previous unit, and the helper `execve`s the real app so nothing stays resident beside it.

  The module **starts disabled** and is the one entry in the strip that has to be switched on explicitly, rather than defaulting to on like every other module. Privacy and demo mode hide app details and logs and disable the controls. Uses the Bun runtime already shipped, plus systemd user services, Git, `ss` and `flock`: no daemon, no packages, no agent hooks and no agent configuration. Containers, remote services and non-HTTP apps are out of scope, and an app must honor its assigned port and refuse a fallback. See [Development apps](docs/apps.md).
- **Web Mode: the desk in a browser, over Tailscale or your own HTTPS certificate** (#25, @TechLuddite). Off by default and set up from SETTINGS. Private HTTPS uses an owned foreground Tailscale Serve mapping on 8788 in front of a loopback backend. Manual HTTPS serves an existing certificate pinned by its SHA-256 fingerprint. Both modes are HTTPS only, and a failed setup never falls back to plain HTTP. Viewers use individually revocable tokens, desktop privacy filters every response on the server, and browsers can change layout only.

- **HARD REFRESH chip and IPC** (#16, @TechLuddite). The first module-strip chip, or `omarchy-shell infomarchy hardRefresh` (`omarchy-shell shell call nixfred.infomarchy hardRefresh` for the overlay), runs a collector pass that bypasses the GitHub activity, external-IP and Grok billing caches. It never bypasses an opt-in, the USAGE visibility gate, the 15-minute Claude refresh limit or the 10-second Grok billing floor.
- **Grok token totals from local session files** (#16, @TechLuddite). When Omarchy has no Grok usage record, per-turn usage records in Grok's `updates.jsonl` supply today's and lifetime tokens per model, falling back to session counts. Today's figure leaves out cache reads, as OpenCode's does. Grok's weekly meter is read from Grok CLI's own log when the CLI has fetched billing itself. Both are file reads with no network access.
- **Optional Grok billing meter and Claude token refresh, both off by default** (#16, @TechLuddite). `INFOMARCHY_ALLOW_GROK_BILLING=1` lets the collector fetch Grok's weekly billing with the Grok CLI credential. `INFOMARCHY_ALLOW_CLAUDE_REFRESH=1` lets the wallpaper collector run `claude -p ping --max-turns 0` when the saved Claude OAuth token has expired, at most once every 15 minutes per machine, then Omarchy's `--limits-only` check. Each runs only while the USAGE card is shown. Claude Code does not document that this refresh makes no model request, so the README treats it as one possible small request against the Claude plan. A saved Grok billing result is ignored once its opt-in is off.

### Fixed
- **Clicking a herdr-hosted card jumps to it again.** Two independent faults, either of which was enough to make the click do nothing. The collector matched a session to its herdr client by comparing socket paths as raw strings, but a herdr client started without `HERDR_SOCKET_PATH` carries no value while the agent's own environment carries the explicit default path, so the two never matched, no client window resolved, and the card said "no client window found". Both sides now resolve an unset socket to the default. Separately, `focusSession()` handled Orca, Boomux and background sessions when there was no window to point at, but not herdr, so a windowless herdr card fell through to `return false`. Herdr draws every workspace inside one window, so the workspace/tab/pane triple is a real address even with no window resolved, and it is used now. Verified live: the card for a Codex session in herdr pane `w44:p1` resolves its window, and the jump focused herdr workspace `w44`.
- **A card in a worktree says what the work is, not which id the directory has.** An agent running in `~/.no-mistakes/worktrees/<hash>/<ULID>` was labelled with the ULID, and the generated topic then echoed it back as "Improving 01M44FH4T8YW63W98ZCHT8FR2N": a card carrying no information at all, shaped like a summary. When a directory name is an opaque id (ULID, hex hash, UUID, bare number) the collector now resolves the project from the repo the worktree came from, through the origin remote that a worktree shares with its parent, and keeps the id as `worktreeId` for the inspector. The same desk card now reads **omaspotify**.
- **A session with no recorded prompts no longer invents a topic.** `localSessionSummary` fell back to a default verb plus the directory name whenever no transcript entries matched, and padded a keywordless result the same way, so cards announced "Improving <project>" while knowing nothing. It now returns nothing in both cases, an opaque id can never become the subject of a topic, and conversational filler ("you", "your", "our") no longer scores as a keyword. The card falls through to the window title, and failing that to a factual line built from what the snapshot actually holds: branch or worktree, changed files, process count and uptime. Facts beat an apology, and "topic unavailable" was an apology.
- **The inspector's CLOSE control no longer collides with the panel's rounded corner.** The drawer inset its content by `pad` alone, so on a theme with a corner radius the top-right CLOSE chip and the bottom-left action row sat inside the curve and read as crammed against the border. Content now clears the arc, which is a no-op on a square theme where the radius is 0. CLOSE itself is glyph-led and tints red on hover, so it reads as a dismiss control rather than another action chip like the ones along the bottom that act on the session.
- **A disk mount with a space in its path reaches the DISK card.** (#41, @GreyforgeLabs) `df` pads its numeric columns but does not quote the mount path, and `parseDfRows()` split every row on whitespace, so a path such as `/run/media/Example/Data Drive` was read as a mount called `/run/media/Example/Data` whose size column was the word `Drive`, so the row failed validation and was dropped. Collection still asks `df` only for `/` and the home directory, so a removable drive mounted somewhere else is not listed. Among the filesystems already queried, the row is now read as a path followed by three trailing numeric columns, so internal spaces and a path that itself ends in digits survive. The `df` header row is still skipped. The first valid row for a full path is kept, a rejected row does not block a later valid row for that same mount, and the btrfs same-pool suppression still keeps the earlier mount. Checked against live `df` output: every mount without a space parses to the same rows as before.
- **An oversized `df` row is skipped before it is parsed.** A line longer than 4096 characters is dropped first. The three numeric columns are taken from the right in one pass, so a long run of spaces cannot make the row scan itself again and again. The 128-character display cap still applies only after a row has parsed.
- **A session running in Orca takes you to its Orca tab, and a background session stops impersonating one.** Orca hands each terminal an `ORCA_TERMINAL_HANDLE`, and the agent inside inherits it, so the desk can jump straight to the tab with `orca terminal switch --terminal <handle>`. It could not before, because an Orca-hosted agent also inherits the terminal Orca itself was launched from: on this desk Orca was started from a Herdr pane, so six unrelated Orca agents all carried the identical `HERDR_PANE_ID=w30:p1` and every one of their cards jumped to that single pane. The inherited id is real and live, which is why it failed silently rather than visibly. Orca is now resolved first and suppresses the inherited multiplexer ids; a tmux session started inside an Orca tab is the agent's own and still resolves. Separately, a daemon-hosted (`--bg`) session was carrying its launcher's pane id too, so it rendered as a twin of the interactive card in the same repo and its click jumped to that other session; a background session now keeps only the host that knows how to attach it.
- **The desk keeps clear of the bar on whichever edge it occupies, and follows it when the bar moves.** The background layer ignores exclusion zones on purpose, so the cards always reserved a fixed 40px strip at the top. A bottom or side bar covered the desk, and the strip stayed when the bar was hidden. The wallpaper host now declares `shell` so Omarchy injects the live bar snapshot, and the inset on the occupied edge is `barSize`, the bar's real thickness. `position`, `barSize` and `barHidden` are read in that binding, so dragging the bar to another edge, resizing it, or hiding it moves the cards without reloading the plugin. With no bar API the desk keeps the previous top strip of 40px times font scale. The Super+D overlay is unchanged, because it already paints above the bar. A hymission stage reservation still indents the left edge, and a left bar adds its thickness inside that.
- **Settings writes merge per field under a lock** (#25, @TechLuddite), so two desk instances or a browser layout change can no longer undo a privacy choice or restore a revoked viewer token.
- **Automatic topic refinement can be switched off, because the loopback test cannot see an SSH forward.** Refinement is gated on `OLLAMA_HOST` being loopback, but that test reads the address rather than the destination: an `ssh -L 11434:localhost:11434` forward answers on `127.0.0.1`, passes the check, and refinement then posts prompt text to another machine. A forward is indistinguishable from a local socket by address, so this does not make the check smarter — `INFOMARCHY_SKIP_REFINEMENT=1` disables automatic refinement outright, checked before both the loopback test and the explicit `INFOMARCHY_ALLOW_REMOTE_OLLAMA` opt-in. Scope is refinement only: inventory polling and explicit LOAD/UNLOAD are unchanged, the latter posting an empty prompt to set model residency rather than session text. Set it in the shell's own environment and restart the shell, since the collectors inherit theirs at launch. It also suits anyone who simply wants a desk that does not refine on its own, on a metered link or a shared box.
- **A control on a session card is reachable by the pointer, and there is now a gate that can tell.** The card's own focus/inspect `MouseArea` is declared after the column holding the card's contents, and in QML declaration order is paint order, so it sat on top of everything inside and swallowed their clicks. Lifting the column with `z` restores the inner controls and costs the card nothing, because text items do not accept mouse events and every other pixel still falls through. The reason this is worth a changelog line is that nothing in the suite could have caught it: the other QML gates match source text or resolve names, and neither can answer whether a pointer reaches a control. `card-stacking.test.ts` drives real synthetic clicks through `qmltestrunner` — which ships with the same qt6-declarative that provides the qmllint the other gates already require — and asserts three things: an inner control takes its own click, the card still takes every other pixel, and with the lift removed the card swallows it, so the bug itself stays proven rather than described.
- **The inspector follows the bot you opened, not whichever shares its pid.** The open drawer is re-resolved against each snapshot so it cannot go stale, but it matched on pid and provider alone — unique until the Grok Bot roster began sharing one process, after which inspecting the sixth bot snapped back to the first four seconds later. It matches the session id too now, and keeps pid+provider as the fallback for providers that report no id.
- **Hermes launched as `python -m hermes_cli.main` shows up on the desk** (#11, @reverb256). Installs without a shebang launcher run Hermes as a Python module, which the provider pattern never matched, so those live sessions were invisible. Service subcommands in that form (`gateway`, `proxy`, `cron` and the rest) stay off the desk, the same way Codex's `app-server` does.
- **The resolved-import QML gate passes on stock Omarchy 4.0.3.** It counted findings produced by the plugin's own video-support fallbacks, `Util.isVideoPath` behind a `typeof` guard and `BackgroundMedia` loaded by URL, which appear only on an Omarchy without video wallpapers. The ceilings therefore depended on which Omarchy ran the test, and 4.0.3 failed at 28 against 26. Those exact findings are now excluded, matched narrowly, and the ceilings tightened to match. Reported by @Tech0001 in #28.
- **Wallpapers keep their proportions on ultrawide and portrait displays** (#28, @Tech0001). The animated-image surface bound `sourceSize` to the display, so every frame was stretched to the output's shape before `PreserveAspectCrop` ran, and the crop could not undo it. Frames now decode at their natural size and the crop does the fitting, on the desk and the overlay alike. A headless Qt test compares real rendered pixels against a plain aspect-preserving crop at ultrawide, landscape and portrait sizes, including resizing a live instance. Frames larger than the display now use more cache memory, which is the stated tradeoff.

### Changed
- **Limit bars show where even pace is.** A bar at 86% means nothing alone: it read as "out of Claude Code" next to Burn Bar's "86% ON PACE", when the number was identical in the Omarchy cache, the collector, the live desk and Burn Bar. What the card lacked was a reference, so each Session and Weekly bar in USAGE & LIMITS now carries a thin tick at the fraction of its window that has already elapsed, taken from the snapshot's own clock. A bar short of the tick is behind pace, a bar past it is ahead, and 86% with 82% of the week gone now reads as slightly ahead instead of simply red. The tick is omitted rather than guessed when the window length is unknown, the reset time is missing or unparseable, the reset is already past, or it is further out than the window itself (a stale reading). The card hint says `| = even pace`. Every other meter on the desk passes no pace and is unchanged.
- **Every session card now says what clicking it will do, including when the answer is nothing.** Four of eight live cards here could not be jumped to and none of them explained why: they are agents started by a supervisor (the harness CLI, the no-mistakes daemon) with no controlling terminal, whose output goes down a socket or pipe to the parent, so there is no window to raise and no pane to select. Those cards now name the owner ("run by harness") and end with "no terminal to jump to" instead of silently swallowing clicks. Where the owner ships its own attach, the click uses it: a no-mistakes worker opens a terminal running `no-mistakes attach` in its worktree, the same shape as a background Claude session attaching with `claude attach`. Harness has no per-agent attach, only `harness tui` and `harness search`, so those cards stay honestly marked rather than being given an invented jump.
- **The inspector can end any session, not only a stale one.** Right-click a card, read what it is doing, and END PROCESS is there. It was previously gated on `stale === true`, so a live agent could be inspected and never stopped, which is backwards: if the desk is where you noticed it, the desk is where you should be able to stop it. Still two clicks, and a live session's confirmation names what it is about to kill (`CONFIRM: END INFOMARCHY`) rather than showing a generic prompt. The arming expires after 4 seconds on its own. Nothing about the signal path changed: it is SIGTERM, never SIGKILL, and `stop-session.ts` re-checks before signalling that the pid still has the start time the card recorded and that its argv is an agent binary, so a recycled pid or an unrelated process is refused.
- **USAGE providers render as separate tinted blocks** (#16, @TechLuddite), and stale Claude sign-in help is hidden once limits load.
- **The desk refreshes when something changes, not only on the timer** (#39, @reverb256). A write to Hermes's `state.db` or its WAL, or to Infomarchy's own `dashboard.json`, pulls the next collect forward after a 250 ms debounce. The repeating refresh (4 s visible, 16 s hidden) stays as the floor, so nothing gets slower when no watched file changes. Paths come from `HOME`, `HERMES_HOME` and `XDG_STATE_HOME`, so the watches work on any machine, and a file that does not exist is simply never watched. The watchers are set to `preload: false`, which keeps FileView from reading a multi-megabyte `state.db` into memory just to watch it.
- **Keyboard shortcut setup is an explicit install step** (#29, @auggernaut). Installing or enabling the plugin never created the `SUPER+I` and `SUPER+D` bindings, yet the desk advertised both, so a fresh install showed a hint that did nothing. The README now has a dedicated section with a conflict check, reload and `hyprctl configerrors` validation, and the direct toggle command for troubleshooting, and every mention of the shortcuts links to it. Added at merge: when the direct command works but the key does not, the cause is Hyprland holding a stale `OMARCHY_PATH` (seen after `omarchy dev link` without a relogin), with the two-line comparison that proves it.

### Notes for maintainers
See `docs/fleet-remote-hosts.md` for the design writeup: why detection reuses `providerOf()` by reference instead of a second copy of `PROVIDERS`, why the store-persisted throttle shape mirrors `github-activity.ts` exactly, the security model for the two `ssh` probes, and everything that was verified live against a real Hermes instance rather than only in the test suite. Also documents a real bug caught before it shipped: `InfoSettings.qml`'s `definitions` array feeds `Overlay.qml`'s keyboard-digit shortcuts positionally (`definitions[n-1]` → digit `n`), so FLEET is appended after MEDIA rather than inserted after LOCAL AI — a mid-list insertion would have silently reassigned PROJECTS off digit `0`.

## [1.4.1] — 2026-09-11

### Changed
- **QML is now checked at two layers, because parsing is not loading.** `qml-syntax.test.ts` proves each file parses; that is a weaker guarantee than it looks, since a property bound to an id that does not exist is valid syntax and still fails on the desk. `qml-resolve.test.ts` resolves the real imports (`qs.Commons`, `qs.Ui`, the Quickshell modules) so qmllint can tell whether a name exists at all. It gates a per-file ceiling rather than zero, because the codebase carries findings that are idiomatic or unmodellable rather than wrong: `[unqualified]` is how QML reads its own root properties, `PanelWindow` is created by the Quickshell runtime so qmllint calls it uncreatable, and `BackgroundWallpaper.qml` deliberately names `BackgroundMedia`, which exists only on an Omarchy with video wallpaper support. A ceiling still catches the case that matters, since one new unresolvable reference moves the count. Verified both ways: injecting `nonexistentThing.value` into `InfoSettings.qml` passes the syntax gate and fails this one. The gate announces a skip when Omarchy or qmllint is absent rather than passing silently.

## [1.4.0] — 2026-09-10

Six community pull requests, integrated and verified together rather than one at a time. Thank you to everyone who sent these.

### Added
- **Antigravity and `agy` are recognised agents** (#24, @alinuxfan, closes #23). Background services — `remote-control start` and `mic-serve` — are excluded the same way Codex's `app-server` is, so only real conversations become cards.
- **Pi sessions, and Recent Tasks that does not bury quiet agents** (#15, @TechLuddite). Pi joins the session and history pipeline, and the recent window now reserves room per provider so a busy Claude week cannot hide OpenCode or Pi, while keeping pinned-first and newest-first order.
- **Optional MEDIA CONTROLS card** (#20, @TechLuddite) over Quickshell's local MPRIS service. Album art is never fetched. A playing player wins; `playerctld` is only a fallback.
- **The LOCAL AI server origin persists** (#18, @TechLuddite) through `setOllamaHost` / `getOllamaHost`. Origins carrying credentials, paths, queries or fragments are rejected, and automatic topic refinement keeps its loopback-only default.
- **Animated image wallpapers** (#22, @TechLuddite). One surface serves stills and animation; the overlay pauses playback while closed.
- **Muse is a recognised agent** (#26, @TRIBUSeric). Detection only — Muse keeps no history on disk yet, so it is deliberately absent from the heatmap legend rather than shown as a chip that can never light up.

### Fixed
- **Observational collection and redaction hardened** (#14, @TechLuddite). Git commands run with filesystem monitors, hooks, external diffs and credential helpers disabled and global configuration ignored — a scanned repository controls all of those, so this closes a real code-execution path. `INFOMARCHY_SKIP_GITHUB=1` now covers CI as well as the activity feed, Herdr focus requires the matching socket, and six more token prefixes are redacted. It also stops treating `0.0.0.0` as loopback, which had let automatic refinement post prompt text to it.

### Changed
- **Every QML file is gated on `qmllint`.** Every other QML check here matches strings against the file text, which cannot tell a valid document from a broken one. Integrating this queue produced an `InfoSettings.qml` with a duplicated property block and a missing comma that passed the whole suite and would have failed to load. Only `[syntax]` findings are gated, so the check holds without the Quickshell type registry.

## [1.3.3] — 2026-09-10

### Added
- **Muse sessions appear on the desk** (#26). Muse installs as a shell launcher on `PATH` that execs the real CLI out of a mise install directory, so the process can present either path; both are recognised. ## [1.3.2] — 2026-09-09

### Changed
- **A busy desk shrinks its session cards instead of burying the rest of itself.** Past eight agents the cards go dense: columns are chosen to bound the number of *rows* rather than the number of cards, and each card drops the working directory, host, window title and repository lines and keeps its topic to one line. Twenty-five sessions went from five rows of eight-line cards — the whole screen, with no ACTIVITY, RECENT TASKS or ops cards under it — to four rows of four-line cards. Nothing is lost: the inspector still carries every field. Measured rather than guessed, and the measuring caught a trap: the minimum card width is multiplied by `fontScale`, so a dense minimum of 138 became 184 on a 1.33 desk, exceeded the fitted width, and made Flow fall back to six per row so the extra columns bought nothing.

## [1.3.1] — 2026-09-08

### Fixed
- **Clicking a Hermes card opens the Hermes app.** It did nothing at all. Hermes is a launcher that spawns its own Electron app and a backend as separate processes, so the window sits *below* the agent in the process tree; window resolution only ever looked upward, at the terminal an agent was started from, and a Hermes card ended up with no window to focus. A descendant is now accepted too, but only when the window's class answers to the provider's own name — otherwise a terminal agent that opened a browser would have its card hijacked by the browser. The card also carries the live session id now, read from Hermes' own lease file, which records the backend pid rather than the launcher the card is built from.
- **Optional read-only REMOTE roster card** (#13, @wulfkaal) from `INFOMARCHY_REMOTE_ROSTER`: bounded local JSON ingest, freshness labels, status counts and compact attention rows beside LOCAL AI. Existing right-column orders migrate automatically; local sessions and notifications stay independent. Optionally, `INFOMARCHY_REMOTE_WORKSPACE` names a workspace and the card becomes a doorway to it: one click focuses that workspace, where the operator's own view of those agents lives. Unset, the card has no interactions at all.

## [1.3.0] — 2026-09-08

### Added
- **Per-model breakdown for every provider.** Anthropic publishes a real rate-limit window per model family, which is where **Fable Weekly** comes from; OpenAI and xAI publish no such window, so the honest equivalent is each model's share of the work. Codex now breaks out `gpt-6-astra` and `codex-auto-review`, Claude shows its models beside their windows, and Grok — which reports no tokens at all — is broken down by sessions per model instead.
- **New models need no code change.** The breakdown is the union of whatever the provider reports in `todayTokensByModel`, `modelUsage` and `modelSessions`, weighted by today's tokens, falling back to lifetime share so a quiet morning still shows the mix, then to sessions where there are no tokens. Not one model name appears in the collector or the view; a test asserts that, ignoring comments.

## [1.2.1] — 2026-09-08

### Fixed
- **Clicking a Herdr card now jumps to that agent's pane.** It focused the Herdr window and left it on whatever workspace was already showing. ## [1.1.0] — 2026-09-07

### Added
- **Hermes sessions in Recent Tasks.** Hermes/TARS stores history in SQLite (`$HERMES_HOME/state.db` or `~/.hermes/state.db`), not a prompt jsonl, so those sessions never appeared next to Claude/Grok. The collector reads each user prompt (280-character `safePrompt` excerpt), skips `cron`/archived/hidden sessions, colours Hermes on the activity heatmap, and resumes with `hermes --resume <id>`.
- **GITHUB · LAST 7 DAYS.** The activity row is now two half-width cards: the AI prompt heatmap on the left and, on the right, the same hour-by-hour grid fed from GitHub — commits, PRs, reviews, issues, comments and other events, coloured by dominant kind, hover for the breakdown and the repositories, today/week counts in the header. Click pins a cell; a legend kind recolours the grid to that kind alone. It is a removable module (**4** in the overlay; the modules after it shift one key and **0** reaches the tenth) and either card takes the full row when the other is hidden.
- **ABOUT.** The version sits at the quiet end of the legend line under the last card — on screen always, never in the way of the data. Clicking it opens ABOUT: the version, a link to the repository, and a link to nixfred.com. The version is read from `manifest.json` at load, so it cannot drift from the version the plugin actually ships as, and `openUrl` refuses any address other than those two. Esc closes ABOUT before it closes the desk.
- **Grok Bot gets a card per bot.** The xAI desktop app runs its whole roster inside one Electron process, so `/proc` can only ever show one agent. Infomarchy reads the app's own local roster (`~/.config/Grok Bot/sand-client-persistence`, one plain-JSON file per state slice, named by the base32 of its key) and expands it into one **Live AI session** card per bot: the bot's name, the last line it wrote (markdown flattened, secrets redacted the same way prompts are), and its **Needs You** state — *waiting for your answer*, or *has replies you have not read* with the count on the card. Hidden-from-sidebar bots get no card, and transcripts are never opened. Because the bots share one process, its CPU/RAM/GPU counters are attributed once — to the bot the app currently has open — and the other cards report `—` rather than repeating the same process nine times. The alert key omits the unread count, so a bot notifies when it goes unread, not again on every further reply.
- **Grok Bot is detected at all.** Electron rewrites its process title, so the whole command line arrives as a single `argv[0]` — and the install path itself contains a space. The browser process is now matched on that line, while the zygote/renderer/gpu/utility helpers (`--type=`) and the `local-exec-daemon` script are not.
- **Grok CLI sessions are counted from disk.** Grok ≥ 1.0 gives every session its own directory under the encoded cwd, so sessions that have not been prompted yet were invisible. `GROK_HOME` is honoured, and a project path too long to encode is read back from the group's `.cwd` file instead of showing as a slug plus a hash.
- `github-activity.ts`: commits from `gh api search/commits` by author date (one row per commit, default branches only), everything else from the user's own events feed; both slimmed by `gh --jq` so no commit message or issue body is ever parsed. A private `github-activity.json` store, written by the wallpaper collector and read by the overlay, fills the week incrementally (one step a minute until covered, then every five minutes, at most a handful of calls per step), pages the events feed until a known id, walks one search query page by page so timestamp ties cannot stall it, re-walks the window every six hours for late-indexed commits, backs off on failures, resets on an account change, and survives restarts and dropped connections as a *stale* grid. `INFOMARCHY_SKIP_GITHUB=1` disables it.

### Changed
- A live Grok card now resolves its own session id from the session files the CLI holds open, instead of inferring one from the project's prompt history.
- Session cards and the inspector print `—` for a resource counter that is genuinely unavailable, rather than `0B` / `0 proc`.
- The heatmap canvas, tooltip and legend are one `HeatPanel` component used by both cards. Card header hints now elide instead of pushing past a half-width card.

## [0.4.0] — 2026-09-05

First marketplace release with the operations desk. Verified on a stock Omarchy 4.0.2 VM (fresh install, no bun → install hint → `pacman -S bun` → desk fills in without a restart), and by two independent Codex reviews (gpt-5.6-sol and gpt-6-astra) whose 60+ confirmed findings were each reproduced before being fixed.

### Added
- **Operations desk**: WHAT CHANGED (per-repository working-tree summary with seen/unseen tracking), NEXT ACTIONS (specific blocked / waiting / review signals with one-click ANSWER / RESOLVE / REVIEW / RESUME), PROJECT HEALTH (branch, dirty state, ahead/behind, last commit, newest GitHub Actions run via authenticated `gh`, click to filter the whole dashboard). All three are draggable and individually removable.
- **Proactive alerts** through Omarchy's notification service: blocked, waiting, ready-for-review, ended, and title-reported crashes; persistent seven-day deduplication with episode tracking; global switch, per-provider mutes, and quiet hours (22:00–08:00). Clicking an alert opens the fullscreen desk.
- **Multiplexer-hosted sessions**: agents inside Herdr, Boomux, or tmux stay visible with their bounded host identity; an attached tmux pane focuses its real client terminal and switches the client to that pane.
- **Ollama controls**: pick any installed model, LOAD (pinned) / UNLOAD per loaded row, size-aware CONFIRM for large models.
- **Hermes** (NousResearch) detected as a provider.
- Session inspector (right-click a card): move to workspace, focus, open a terminal in the project, toggle hover previews.
- Prompt search, pinning, and per-cell heatmap drill-down; recent rows shipped up to 1,000 for a full week.
- `CHANGELOG.md`, and a `bun` install step in the README (Omarchy does not ship bun).

### Changed
- Collector output is one awaited write; snapshots are capped at 960 KiB, below the shell-side limit, so a valid frame can never be rejected.
- Every external JSON source (histories, usage caches, Ollama, hyprctl, gh) is parsed through one bounded, coercion-safe path; malformed or hostile content degrades a single card, never the desk.
- Automatic topic refinement talks only to a loopback Ollama unless `INFOMARCHY_ALLOW_REMOTE_OLLAMA=1` is set — prompt text does not leave the machine by default.
- Demo mode now covers the SUPER+D overlay as well as the wallpaper.
- Credential redaction covers env-style assignments, credentials in URLs, PEM blocks, JWTs, and common cloud key shapes (best effort).
- Provider detection matches the executable only (or a script run by a known interpreter): `cat /tmp/claude` is no longer an agent.
- Attention signals are evaluated only for idle agents; a title that mentions "permission" or "failed" mid-task no longer alerts.
- The collector keeps running at a quarter cadence while the desk is hidden so alerts still arrive; it stops entirely only when alerts are off too.
- Throughput is displayed in bits/s; COPY PROMPT is now COPY EXCERPT (140-character redacted excerpt).

### Fixed
- Desk went blank on: a `%` in a Grok session directory name, a non-array `active_sessions.json`, a nested object in a Grok pid, a null entry from `hyprctl clients`, `{"toString":0}` anywhere in external JSON, two large usage caches, and a `history.jsonl` over 8 MB (Claude then showed as "not installed"). All degrade gracefully now.
- Desk froze when a killed helper left a child holding its pipe (`gh` → `git`, shell → `sleep`); the collector now abandons the pipe at its deadline and exits explicitly.
- Ollama LOAD / UNLOAD never completed (helper waited for stdin EOF that Quickshell never sends).
- Topic refinement cached its own timeouts as summaries and never retried; Codex rows had no project and RESUME opened `$HOME`; pinned prompts vanished past 80 rows; quiet-hours and muted alerts were marked delivered and never shown; the first snapshot after a restart dropped ended-session events.
- Display escaping corrupted paths and clipboard text (`~/R&D` → `~/R＆D`); `/home/pi2` was treated as inside `/home/pi`; Git paths with non-ASCII characters were shown as octal escapes.
- Session inference could bind a live agent to a later session's prompts or steal an id another live agent owned.
- Resource leaks: preview temp directories, orphaned state temp files, unbounded topic/pin/mute/seen maps, per-tick full scans of `opencode.db`, unbounded git/gh/Ollama fan-out, rollout enumeration past the cap.
- Inspector drawer froze on stale data; the wallpaper search box could never receive keystrokes; busy/attention animations ran while hidden; garbage `nvidia-smi` / `df` / `ping` output rendered as an empty GPU, a null disk, or a QML binding error.
